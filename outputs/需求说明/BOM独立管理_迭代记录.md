# BOM 独立管理迭代记录

## 2026-10-27：ME 退回对象

- 需求已确认：ME 确认工作版本时，可选择退回至 AE 或 SCM。
- 已实现：ME 的“退回修改”弹窗提供接收角色选择及必填退回说明；SCM 视角继续退回 AE。
- 已实现：退回接收人可编辑、保存草稿并重新提交；保存草稿保留接收人，其他角色不得接手该退回版本。重新提交后，所选确认人员重新确认。
- 已实现：列表展示退回去向；退回接收角色、人员、说明及操作时间保留在版本和操作记录中。
- 验证：脚本语法及逻辑测试通过，覆盖 ME 退回 SCM、必填说明、接收人权限、保存草稿后继续修改、SCM 重新提交和 SCM 退回 AE。尚未由用户验收。

## 2026-10-27：版本生成与顺序确认（取代此前并行确认逻辑）

- 需求已确认：SCM 固定第一位，其他确认人员按添加顺序依次处理；任一人员退回暂停本轮，由其选择 AE 或 SCM 调整。SCM 自己退回时交给 AE。
- 需求已确认：调整后重新提交，从 SCM 开始新一轮确认，沿用原版本号；全部通过才锁定生效。
- 已实现：新建 BOM、保存草稿不分配版本号，首次提交生成 V1；SCM 可编辑后确认或直接确认，均不升版。生效版本再次变更，工作草稿提交时才生成下一版本，原生效版本持续有效直到新版本全部通过。
- 已实现：确认结果按人员标识保存，同一角色的多名人员可逐人确认；仅 SCM 在自己的确认节点可编辑，其他确认人员通过确认或退回处理。
- 已实现：清单展示确认顺序及“待确认 / 待前序确认 / 本轮已暂停”；退回接收人负责修改和重新提交，完整保留各轮操作及退回时 BOM 快照。
- 已实现：增加 AQE 和第二名 ME 模拟身份；新增三条“流程演示”数据，分别展示待 SCM、待 ME、ME 退回 SCM 的情况。
- 兼容：保留用户已有 BOM，迁移已有待确认数据为从 SCM 开始；迁移前数据保存在浏览器本地备份键 bw-independent-bom-v1-before-sequential。
- 验证：tests/bom-sequential-workflow.cjs 逻辑测试通过，涵盖多人顺序、同角色不同人员、退回暂停、接收权限、SCM 修改重提、跨轮不升版、历史快照和 V2 提交时生成。浏览器工具因 file 协议限制无法执行页面视觉检查，尚未由用户验收。

- 已按用户反馈实现：退回 SCM 后调整并重新提交，在确认记录中单独展示“SCM 调整后重新提交”，状态为“已提交”，保留操作人、实际重新提交时间及轮次，与后续“SCM 确认”分开呈现。历史已存的重新提交事件兼容该展示规则，未发生的事件不补造时间。
- 验证：流程测试增加不同时间点的重新提交及节点展示断言。

## 2026-10-27：SCM 提交即确认（覆盖此前重复确认规则）

- 已按用户反馈实现：SCM 首次编辑后“保存并提交”，以及收到退回后调整并重新提交，均视为完成本轮 SCM 确认，直接流转至下一位；仅保存修改不推进。AE 重新提交仍需 SCM 确认。
- SCM 提交事件继续单独保留人员、时间和轮次，不额外生成重复确认记录；若仅配置 SCM，则提交后完成全部确认并生效。
- 兼容修正：已存的 SCM 重新提交但仍停留 SCM 待确认的数据，刷新后依据实际提交记录推进，不补造时间。
- 逻辑测试通过：首次编辑的保存／提交差异、退回重提、无重复 SCM 节点、仅 SCM 的生效、已有数据兼容。业务说明和 UML 图同步调整。
