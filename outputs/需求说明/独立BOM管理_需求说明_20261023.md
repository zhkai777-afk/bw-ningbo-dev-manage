# 独立 BOM 管理需求说明

文档版本：R1（需求评审稿）  
编制日期：2026-10-23  
适用页面：`BOM独立管理.html`，包含列表、手动创建、BOM 编辑、BOM 明细、版本记录及确认记录。  
编制依据：本轮用户明确规则、此前页面迭代确认事项、项目业务规则及当前 HTML。本文描述目标需求，不代表全部功能已经实现或验收。

## 1. 目标与范围

独立 BOM 管理用于承接已完成项目和已完成独立 APQP 的 BOM，支持后续结构维护、版本变更及人员确认。来源模块和本模块必须保持明确关联，避免形成两套互不一致的 BOM。

本模块还支持手动创建 BOM，归属类型可选择“项目开发”或“零件 APQP”。手动创建与来源模块创建通过“类型”区分，不单独设置手动创建页签。

本次核心需求为：

1. 项目开发创建的 BOM，在来源项目状态为“已完成”后，进入本模块“项目开发”页签；进入时展示该 BOM 的最新工作版本。
2. 独立创建的零件 APQP，其 BOM 在该 APQP 自身状态为“已完成”后，进入本模块“零件 APQP”页签；进入时展示该 BOM 的最新工作版本。
3. 本模块支持编辑并提交确认。确认完成后的 BOM 版本、完整结构及零件信息必须同步至对应来源项目或独立 APQP，两侧查看同一确认版本时内容一致。
4. 由项目创建的 APQP，其 BOM 不进入独立 BOM 管理的“零件 APQP”页签，避免与项目 BOM 重复管理。此规则不因该 APQP 已完成而改变。

## 2. 术语及数据归属

| 术语 | 定义 |
| --- | --- |
| 来源对象 | 创建 BOM 的项目开发记录或独立 APQP 记录，不是本模块的页签名称 |
| 项目创建的 APQP | 在项目开发流程中创建、带有明确项目创建来源的 APQP；不是指所有填写了所属项目的 APQP |
| 独立 APQP | 在 APQP 模块独立创建的开发对象；可以关联项目，但不因此自动变成“项目创建的 APQP” |
| 最新工作版本 | 同一 BOM 版本链中最新的工作版本，可能尚未确认；不得直接以旧的已生效版本替代 |
| 当前生效版本 | 已完成所需确认、锁定生效的版本，与最新工作版本分别表达 |
| BOM 归属类型 | 项目开发 / 零件 APQP，决定进入哪个业务页签 |
| 创建类型 | 本模块手动创建 / 项目开发模块创建 / 零件 APQP 模块创建 |

项目 BOM 容器不承载项目整体业务版本号，L1 总成的独立版本边界继续遵循项目规则。页面允许展示多棵并级零件结构，不应据此将不同 L1 的独立版本链合并为一个项目整体版本。

## 3. 来源准入与列表展示

### 3.1 展示规则（BR-01）

| BOM 创建来源 | 来源状态 | 项目开发页签 | 零件 APQP 页签 | 说明 |
| --- | --- | --- | --- | --- |
| 项目开发模块创建 | 项目未完成 | 不展示 | 不展示 | 保留在来源模块按原流程管理 |
| 项目开发模块创建 | 项目已完成 | 展示 | 不展示 | 使用该来源 BOM 的最新工作版本 |
| APQP 模块独立创建 | APQP 未完成 | 不展示 | 不展示 | 不以关联项目完成代替 APQP 自身完成 |
| APQP 模块独立创建 | APQP 已完成 | 不展示 | 展示 | 使用该 APQP BOM 的最新工作版本 |
| 由项目创建的 APQP | 任意状态 | 不作为 APQP 单独新增记录 | 不展示 | 项目 BOM 仍按来源项目的规则进入项目开发页签 |
| 本模块手动创建，归属项目开发 | 草稿或后续状态 | 展示 | 不展示 | 不套用来源项目完成的准入限制 |
| 本模块手动创建，归属零件 APQP | 草稿或后续状态 | 不展示 | 展示 | 不套用来源 APQP 完成的准入限制 |

“来源已完成”和“BOM 已确认”是不同条件。来源完成后应展示最新工作版本并说明其真实状态；不能因为最新工作版本未确认，就只展示较早的已生效版本。

来源完成事件重复触发、页面刷新或重新读取数据，不得生成重复的独立 BOM 记录。已有来源关联和版本标识应延续，不为“进入本模块”额外复制出无关联的业务版本。

### 3.2 APQP 排除规则（BR-02）

系统必须保存并识别 APQP 的实际创建来源。判断顺序为：

1. 判断是否为“项目创建的 APQP”。如果是，排除其在独立 BOM—零件 APQP 页签的展示。
2. 如果是独立创建的 APQP，再判断该 APQP 自身是否已完成。
3. 符合准入后，关联其最新工作版本。

不得仅依据“所属项目是否为空”判断 APQP 创建来源。独立创建、后续关联了项目的 APQP，仍按独立 APQP 规则处理；来源信息缺失时，不得擅自认定为独立创建，应列为数据待核实项。

### 3.3 列表及查询

| 页签 | 列表字段 |
| --- | --- |
| 项目开发 | 勾选、项目名称、类型、客户、产品、系统、生效版本所出阶段、最新版本、版本状态、操作 |
| 零件 APQP | 勾选、项目名称、类型、所属项目、产品质量流程、供应商、生效版本所出阶段、最新版本、版本状态、操作 |

查询条件与页签对应，包含项目名称、业务属性、BW 零件号及类型筛选。列表不展示“项目编号”“客户项目”，不提供这两个独立检索条件；内部关联标识继续保留。

状态概览包含全部、待提交、待确认、已锁定。查询、概览、批量操作应遵守相同的业务归属及来源准入范围。点击“明细”查看版本及结构，点击“确认记录”查看提交与确认过程。

## 4. 编辑、确认与跨模块同步

### 4.1 来源进入时的版本处理（BR-03）

例如：来源项目完成时，BOM 当前生效版本为 V2，最新工作版本为 V3 草稿。本模块应展示 V3 及草稿状态，同时保留 V2 作为生效基线；不得将 V2 标记为最新版本，也不得将 V3 自动标记为已确认。

进入本模块不应自动完成审批、不应覆盖版本历史，也不应仅因入口变化升版。已有待确认版本的确认结果、确认人员及历史记录需要保留；是否允许切换处理入口见第 9 节。

### 4.2 维护流程（BR-04）

1. 有权限的维护人员进入 BOM 编辑页，查看对应来源对象及版本。
2. 编辑工作版本的零件信息、结构或其他允许修改的属性，填写变更说明，指定确认人员。
3. 保存草稿后，保留工作内容；“保存并提交”进行必需信息、结构和确认人员校验。
4. 所选人员分别确认；全部完成后，该版本锁定生效。部分人员确认不能触发同步生效。
5. 确认人员退回时，填写退回意见；整改并重新提交后按更新版本重新确认，不能沿用失效的旧确认结果。
6. 修改已生效 BOM 时建立新的工作版本，保留旧版本及其确认记录，不直接改写历史快照。

版本号采用 V1、V2、V3 递增格式，不拼接项目阶段；版本生成阶段独立保存。版本号递增应在统一的版本链内处理，不能在来源端和独立端分别计数。

### 4.3 确认后的同步要求（BR-05）

确认完成后，同步对象为该记录的原始来源：

| 本模块归属 | 同步目标 | 必须一致的内容 |
| --- | --- | --- |
| 项目开发模块创建的 BOM | 对应来源项目的对应 BOM | 确认版本号、版本标识、确认状态、完整结构及全部 BOM 行属性 |
| 独立 APQP 创建的 BOM | 对应来源独立 APQP 的对应 BOM | 确认版本号、版本标识、确认状态、完整结构及全部 BOM 行属性 |
| 本模块手动创建的 BOM | 无来源对象时不回传 | 仅按本模块记录管理，不虚构来源项目或 APQP；后续关联规则另行确认 |

同步范围包含根零件、全部子级、父子关系、层级、数量、零件号、名称、产品应用、图纸、材料、重量、供应属性、备注及本版本变更说明。不能仅同步根零件或版本号。

两侧查看同一已确认版本时，应能核对以下一致性：

- 同一 BOM 业务标识和版本标识，版本号一致。
- 根零件数量、BOM 行数量、各行父子关系与字段值一致。
- 确认人员、确认结果及生效状态一致。
- 刷新、退出后重新进入仍一致，不依赖临时浏览器缓存。

例如：本模块将 V3 的某子零件数量由 2 改为 3，确认完成后，来源项目或独立 APQP 应展示对应 V3 结构，数量为 3。原 V2 历史仍保留数量 2，不被覆盖。

### 4.4 一致性及异常处理要求（BR-06）

以下为实现上述同步要求必须满足的结果约束，具体技术方案由研发确定：

- 两侧关联同一 BOM 对象及版本链，避免各自维护无法对齐的副本。
- 确认、生效和来源更新应保证一致；发生同步失败时，不得提示两侧已经同步成功，必须明确待处理状态并可重试。
- 重复提交确认请求或重复同步，不得重复升版或重复新增结构。
- 保存或确认前校验版本是否被其他人员更新，发生冲突时保留输入并提示处理，不能静默覆盖。
- 关联来源对象不存在或不匹配时，说明具体对象及失败原因，不将版本写入其他项目或 APQP。
- 记录来源对象、修改人、版本、确认人、确认时间及同步结果，能够追溯一次确认对应的两端变化。

来源端是否允许继续编辑，以及未确认草稿在两侧的可见范围，尚需确认。无论采用何种方案，已确认版本及结构必须满足本节的一致性要求。

## 5. 手动创建与 BOM 结构维护

### 5.1 手动创建

表单包含 BOM 归属类型、项目名称、客户、产品和系统。归属类型必选“项目开发”或“零件 APQP”，默认当前页签但允许修改；产品多选，系统由产品自动汇总。

手动创建的记录以“本模块手动创建”展示在所选归属页签。它的“业务归属”不代表已经存在可同步的来源对象。

### 5.2 添加及维护结构

- 新建 BOM 默认空列表，提供“从 SAP 添加”“手动添加”两张选择卡片及操作说明。
- SAP 方式要求输入零件号查询，可用名称辅助筛选；选择后带入该零件的整体结构，后续可调整。
- 手动方式通过统一弹窗录入零件信息，根零件层级可输入。
- 支持多棵并级根结构，可混合使用 SAP 和手动添加；同一 SAP 候选也允许重复加入，每次生成独立行标识及父子关系。
- 单选一行后提供“从 SAP 添加子级”“手动添加子级”，自动采用当前选中行为父级；多选不执行子级新增。
- 删除零件时明确对象和子树范围，二次确认；只影响当前工作版本对应子树，历史快照及已有开发任务追溯不得物理抹除。
- 当前原型支持 L1 至 L4；子级必须关联上一层级的有效父级，不能产生循环或断裂结构。超出支持范围时说明原因，不静默截断 SAP 结构。

### 5.3 零件字段及校验

| 分组 | 字段 |
| --- | --- |
| 关键信息 | 层级、数量、供应类型、APQP 负责人、零件/材料名称、产品应用 |
| 编码信息 | 客户零件号、BW 零件号、图纸版本、样件 SAP 零件号、量产 SAP 零件号 |
| 材料、重量与图纸 | 原材料零件号、原材料、Piece 重量、Assembly 重量、共用零件、借用项目、图纸状态、原材料供应商、分供方、备注 |

名称及 BW 零件号必填，数量大于 0，重量如填写则为非负数。错误提示应说明缺失字段或异常关系，并尽量定位对应行，不清空已录入内容。

## 6. 确认人员与版本追溯

确认人员默认以紧凑列表展示，点击“添加确认人员”后按需打开规范中的组织架构型穿梭框。组件支持分组、搜索、多选、添加及移除；点击“确认选择”回填，取消或关闭不改变原名单。

草稿可以暂不指定确认人员；提交时至少指定一人。仅指定人员可以执行该版本确认，所选人员全部确认后才锁定生效。确认人员配置随版本保留，不能因后续默认组织或人员设置变化而修改历史记录。

详情窗口包含两个页签：

| 页签 | 内容 |
| --- | --- |
| BOM 明细 | 按版本查看完整结构、BW 零件号查询、版本状态及导出 |
| 版本记录 | 表格字段：版本号、创建日期、创建人、版本记录、确认人；版本号可定位对应版本明细 |

创建日期、创建人生成后保留，不使用后续确认时间冒充创建时间。确认记录另行展示提交人、确认人、处理结果、意见及时间。旧记录缺少可靠创建信息时显示“—”，不得编造。

## 7. 界面与业务边界

- 列表及编辑工作区随窗口展开；宽表铺满容器并支持自身横向滚动，关键字段完整显示，BOM 行不自动折行或省略截断，操作列固定右侧。
- 主编辑页采用独立页面；变更说明和确认人员列表上下紧凑排列。零件录入、确认及危险操作使用项目统一弹窗，禁止浏览器默认 alert、confirm、prompt。
- SAP 导入、手动录入和版本确认均不应自动创建或取消子零件开发任务；已有任务按来源版本、BOM 行及供应方案保留追溯，后续影响分析遵循项目业务规则。
- 子零件开发、供应商开发及子零件 APQP 的状态只能作为协同和风险信息，不作为项目 Gate 的系统硬阻塞。本模块后续 BOM 维护不自动重开项目 Gate。

## 8. 关键验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 项目进行中且存在 BOM | 独立 BOM 两页签均不因该项目新增来源记录 |
| AC-02 | 项目完成，生效版本 V2、最新工作版本 V3 | 项目开发页签展示该 BOM 的 V3，真实标识状态，V2 历史保留 |
| AC-03 | 同一项目完成通知重复触发 | 不新增重复来源记录、不额外升版 |
| AC-04 | 独立 APQP 未完成，但其关联项目已完成 | 不进入零件 APQP 页签 |
| AC-05 | 独立 APQP 自身完成 | 进入零件 APQP 页签，展示其最新工作版本 |
| AC-06 | 由项目创建的 APQP 完成 | 不进入独立 BOM—零件 APQP 页签；项目 BOM 按项目规则展示 |
| AC-07 | 独立创建的 APQP 后续关联了项目并完成 | 不因存在项目关联而误判为项目创建；按独立 APQP 展示 |
| AC-08 | 本模块修改项目 BOM，指定两人，仅一人确认 | 不作为最终确认版本同步生效，保留另一人待确认 |
| AC-09 | 项目来源 BOM 全部确认 | 来源项目与本模块同版本号、同版本标识、同结构及字段值；旧版历史不变 |
| AC-10 | 独立 APQP 来源 BOM 全部确认 | 来源 APQP 与本模块满足同样一致性要求 |
| AC-11 | 同步请求失败或重复执行 | 失败明确提示并可恢复；重复请求不重复升版或新增零件 |
| AC-12 | 两人基于同一旧版并发编辑 | 不静默覆盖已提交的新内容，提示冲突并保留输入 |
| AC-13 | 手动创建时改选业务归属类型 | 按用户选择进入对应页签，类型为本模块手动创建，不受外部来源完成状态限制 |
| AC-14 | 同一 SAP 零件重复导入、再混合手动新增 | 允许多个并级根，各自子树及行标识独立，可保存并正确追溯 |
| AC-15 | 来源 BOM 不存在或为空 | 不伪造版本和结构；给出可处理提示，具体异常入口见待确认项 |

## 9. 待确认事项

以下事项不影响已经明确的两条来源规则和确认后同步要求，但在实现前需要补充边界：

| 编号 | 待确认内容 | 建议及影响 |
| --- | --- | --- |
| D-01 | “已完成”对应项目及 APQP 的实际状态代码 | 项目阶段结束、任务完成、审批通过不能未经映射就代替对象已完成；需业务和开发对齐字段 |
| D-02 | 来源端是否可见本模块未确认草稿、是否继续允许编辑 | 建议两侧共享版本链，明确工作版本与生效版本；需定义各角色可见范围及编辑入口，避免双端覆盖 |
| D-03 | 来源进入时已有待确认流程如何衔接 | 建议保留原人员、结果和记录，同一版本不得并行发起两套确认流程；入口切换及权限需明确 |
| D-04 | 来源对象完成后重新打开、撤销完成或取消 | 需明确列表是否继续保留、是否暂停编辑；不得直接删除已经维护的版本和历史 |
| D-05 | 手动 BOM 后续关联已有项目/APQP 是否可回写 | 当前仅业务归属不构成同步授权；需明确关联入口、准入状态和冲突处理 |
| D-06 | 来源完成但无 BOM、无有效工作版本的展示方式 | 建议使用异常提示或待处理清单，不能自动生成假 BOM；由业务决定是否出现空记录 |
| D-07 | 多 L1 项目在列表中的行粒度 | 需确认一行项目汇总还是一行 L1；无论表现形式如何，不改变 L1 独立版本管理原则 |
